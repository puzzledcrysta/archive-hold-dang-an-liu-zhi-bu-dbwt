# 档案留置簿数据字典

## 来源文件

| 字段 | 定义 |
|---|---|
| 档案件 | 文本主键，保留前导零。跨业务键不汇并记录。 |
| 修订号 | 正整数。最高版优先；最高同版字段冲突或存在同版、更新版的未采信记录时隔离，旧版无法接替。 |
| 提交时间 | ISO 8601，必须带 UTC 偏移量。标准化后展示 UTC。 |
| 原始备注 | 可空，允许引号内换行。 |
| 结案日、查询日、保管政策、留置区段 | 必填字段。多项字段用半角分号隔开，显式空集合用 `无`。 |

识别 `UTF-8`、UTF-8 BOM 与独立的 `GB18030` 文件。`业务编号`、`版本`、`更新时刻`、`备注` 为旧版表头别名。新旧名同时出现会被拒绝。`-`、`N/A`、`NULL`、`未知` 和空串均按必填值缺失处理。物理行号指 CSV 逻辑记录起始行。

## 计算字段

政策写 `起始日期/结束日期/保管周年`，留置写 `开始日期/结束日期`，均为左闭右开。

闰日的周年落在非闰年时以 3 月 1 日计。处置日期遇到留置顺延到该段末端，续接留置继续顺延。

数值在服务端以十进制定点方式计算，对外按字符串传输。单文件上限 128 KiB，复合字段最多 240 个项目，个别字段还有业务上限。格式无法恢复的 CSV 整批拒绝，列数、缺字段、来源冲突和业务条件错误逐条隔离。

## 复算与外部清单

外部清单包含 `档案件` 和 `外部记录值(天)`，允许省略不在对账范围内的键。同一键重复会拒绝该清单。结果数值单位为 **天**。差值按本次复算减外部记录，缺一侧时差值计算以 0 占位并保留缺失原因。

同一对输入字节与规则版本生成同一批次，导出包含两个文件摘要、证据行、单边差异和复核修订记录。复核保存前检查当前版本，在有隔离、差异或退回时必须填写意见。

## 留置补报

批次完成「确认」复核后，工作台接收迟到的留置补报。补报为两列 CSV：`档案件,留置区段`，区段沿用左闭右开 `开始/结束` 写法，多项用半角分号隔开；同一补报内档案件不得重复，且必须命中原批次的可采信记录，否则整份补报拒绝且不落任何记录。

补报在原批次可采信记录上**叠加**新留置区段后逐件重走处置日规则，并对整批重新对账。原批次、原确认与当时依据保持不变，补报按 `规则版本:批次:补报字节` 内容寻址生成 `supplement_id`：重跑同一补报直接返回已存记录（`duplicated=true`），不重复撤回、不重复记账。

处置日或保护天数发生变化的档案进入**冻结**：差异核清前 `GET /api/runs/{id}/release` 中这些档案 `releasable=false`，旧确认不能再放行；同批其他档案不受影响、照常放行。登记新的「确认」复核即视为核清，冻结解除并记录 `cleared_version`；登记「退回」则已核清补报重新冻结。有未核清补报时复核必须填写意见。

| 接口 | 用途 |
|---|---|
| `POST /api/runs/{id}/supplements` | 提交补报（文本或 base64 原始文件） |
| `GET /api/runs/{id}/supplements` | 批次下全部补报与冻结状态 |
| `GET /api/runs/{id}/supplements/{supplement_id}` | 单次补报的受影响档案、前后计量与重对账 |
| `GET /api/runs/{id}/effective` | 叠加全部补报后的当前生效视图 |
| `GET /api/runs/{id}/release` | 逐件放行闸口 |
